# Eddy

A river-trip planning app: a library of rivers plus any number of trips on them.
Trips (itinerary, crew & crafts, meals, gear, shuttle, ledger, log) are saved
separately and each belongs to a river; the River tab shows map, rapids, camps,
hikes, geology, guide, almanac and rules for the river you pick. Built-in
rivers (27): Grand Canyon (full data) plus Smith, Rogue, Main Salmon, Middle
Fork Salmon, Selway, Hells Canyon, Yampa, Lodore, Green (Flaming Gorge), Desolation-Gray,
Cataract, Westwater, Ruby-Horsethief, San Juan, Rio Chama,
Salt, Illinois and Tuolumne. Eight more are preliminary entries (Alsek, Tatshenshini,
Bruneau-Jarbidge, Deschutes, John Day, Owyhee, Green River Labyrinth/Stillwater and Dolores):
reach, access points and permit rules only, generated by `scripts/rivers/permit-only.cjs`.
The scope is the permitted rivers on American Whitewater's permit list. The others have rapids, camps, access
points, rules, a regional species guide and almanac (history, Indigenous
homeland notes, geology, flows). Camp sizes and ratings, and some hike times, are
still blank where no source gave them. Each river also has an Overview tab (class, season, elevation, gradient,
recommended flow, gauges).

Add or edit rivers in **River -> Rivers** (form editor, or paste/import river
JSON; "Copy JSON" exports one). Rivers you add or edit are stored with your
trips (localStorage, and the shared db when available).

## Layout

- `src/App.jsx` - the whole app (React, single file)
- `src/rivers.js` - river library (built-ins + `normalizeRiver`)
- `src/shell.html` - page shell: fonts, textures, base CSS, `<div id="root">`
- `src/ui.css` - UI polish layer (type scale, unified form controls, 44px tap targets, cards, buttons); inlined after the shell CSS by the build
- `data/rivers/*.json` - built-in river records
- `data/gear.json`, `data/general.json`, `data/trip.json` - gear catalog, safety reference, seeded Grand Canyon trip
- `build.mjs` - bundles `App.jsx` with esbuild, inlines it into the shell and wraps it in a full HTML document -> `index.html`
- `index.html` - **generated**; this is what GitHub Pages serves. Do not edit by hand.
- `src/TopoMap.jsx` - River > Map > Topo map (Leaflet): terrain basemap, pins, dropped pins, sun & shade day timeline, offline download
- `src/SunChart.jsx` - the skyline-and-sun-path chart for a camp or dropped pin
- `src/geo/` - geo code shared by the app and the build: centerline (`line.js`), sun position and canyon sun times (`sun.js`), horizon casting (`horizon.js`), DEM tiles (`dem.js`) and their offline store (`store.js`), shade worker pool (`shade.js`), per-river state, dropped pins and GPX tracks (`index.js`)
- `src/BasinMap.jsx`, `src/geo/basin.js` - River > Map > Basin: the drainage basin above the take-out (streams by size, basin outline, reservoirs and lakes, dams, the trip's run). Draws from `data/basin/<river>.json` with no map tiles, so it works offline
- `data/basin/*.json` - **generated** by `python3 scripts/basin/build.py` (see below); `index.json` lists the rivers that have one
- `scripts/basin/` - the basin pipeline: `rivers.json` (per river: HU4 group, main-stem name, put-in or take-out point), `dams.json` (reservoir name -> dam name), `build.py`
- `data/geo/anchors.json` - Grand Canyon only: known `{mile, lat, lon}` points its centerline is traced between on the terrain (an anchor with `"snap": 0` is used exactly, not snapped to the lowest nearby cell: for surveyed river-mile points on a reservoir, where the DEM is flat water)
- `data/geo/nhd/<river>.json` - **generated** by `python3 scripts/basin/centerline.py`: every other river's centerline, the USGS stream line along the trip's run with the guide's miles pinned to it
- `data/geo/<river>.json` - **generated** by `npm run geo`: centerline + a terrain horizon for every camp (the 19 rivers that have one)

## Build

    npm install
    npm run build

## River record shape

`name`, `reach`, `agency`, `miles: [start, end]`, `coords: [lat, lon]` (put-in, for
sunrise/sunset), `tz`, `days` (typical trip length), `access[]` (put-ins,
take-outs, hubs: `{name, mile?, road?, hub?, park?, note?}`), and optional
`rapids[]`, `camps[]`, `hikes[]`, `geology[]`, `guide[]`, `almanac{}`, `rules[]`,
`landmarks[]`, `clusters[]`, `notes{camp,hike}`, `hdiff{}`, `roads[]`, `stats{}`. See
`data/rivers/grand-canyon.json`. Missing fields are filled in by `normalizeRiver`.

`stats` feeds the River > Overview tab, and every field is optional:

    stats: {
      class: 'III to IV',                 // published reach rating
      season: 'Year-round. Runoff peaks May to June.',
      elev: [3950, 3700],                 // put-in, take-out, feet
      gradient: 2.6,                      // average ft/mi
      steep: { gradient: 18, from: 57.8, miles: 5 },   // steepest stretch
      flow: { min: 3500, typical: 27000, max: 50000, note: '...' },   // cfs
      bands: [{ upto: 25000, label: 'Class III', d: '...' }],         // what each flow feels like
      craft: ['Raft', 'Kayak'],           // good for
      gauges: [{ name: 'Colorado River near Cisco, UT', id: '09180500' }]   // id links to USGS
    }

`flowDoy` (a sibling of `stats`) is **generated**, not hand-edited: `python3 scripts/rivers/flows.py [river-id]` pulls USGS daily
mean discharge for the gauges chosen in that script and stores 53 weekly points of the 25th, 50th and 75th percentile (`p25`, `p50`, `p75`,
from 1 Jan every 7 days, cfs) plus the gauge ids, years used, `regime` (`natural` or `regulated`) and a `where` sentence. A trip's Notes tab shows the point
for the trip's middle day. A river with no gauge chosen has no `flowDoy`. (The `.js` scripts in this folder are the old generators; this one only adds `flowDoy`.)

`climateDoy` is also **generated**: `python3 scripts/rivers/weather.py [river-id]` stores 53 weekly points (average high and low `hi`/`lo`, a hot
afternoon and a cold night `hi90`/`lo10`, percent of days with rain `rain`, average `cloud` percent) from Open-Meteo's 1991 to 2020 archive, adjusted to the river's
height. Open-Meteo has a daily request limit, so a run can stop part way; rerun the rivers missing `climateDoy` the next day.

`elev`, `gradient` and `steep` are measured, not written by hand: `node scripts/geo/elevation.mjs --write` samples the
terrain along each river's centerline (rounded to 50 ft; a dam at the start can distort it, which can distort it). `flow.min` / `max` are the range a guide or agency recommends for rafts where one is given, with the note
saying which gauge and where another source differs. Edit them in River > More > Edit.

## Basin maps

`data/basin/<river>.json` is built from the USGS National Hydrography Dataset (high resolution, one GeoPackage per
4-digit hydrologic unit) and Watershed Boundary Dataset, both public domain. For each river `scripts/basin/build.py`
snaps the put-in (or take-out) to the named main stem, walks the guide's run length to find the other end, traces
every natural channel upstream of the take-out, keeps the biggest channels that fit a size budget, outlines the
basin from the HUC12 watersheds that hold those channels, and picks the biggest reservoirs and lakes. A dam marker
goes at each reservoir's outlet, but only for reservoirs named in `dams.json`; the dam's name comes from there.

    pip install geopandas pyogrio shapely numpy pandas      # matplotlib too for --preview
    python3 scripts/basin/build.py                           # all rivers (downloads about 5 GB into .cache/basin once)
    python3 scripts/basin/build.py dolores --preview /tmp/p  # one river, with a PNG to check
    python3 scripts/basin/build.py --list-reservoirs         # what it would label, to fill in dams.json
    python3 scripts/basin/build.py --dams-only               # after editing dams.json: re-apply it in seconds
    npm test                                                 # checks every file decodes and lines up

Things worth knowing:

- A trip that ends on a bigger river (Yampa, Middle Fork Salmon) uses `basin_until` so the basin stops at the
  tributary's mouth; the map then says "the whole ... basin". Add a river by giving it an entry in `rivers.json`.
- The flow table has no link across a dam, so the script joins a named channel's loose end to the same-named channel
  that starts within about a kilometre below it (and a tributary that stops a few metres short of the river it joins).
  Without that, Hells Canyon would stop at Oxbow Dam and Black Canyon at Hoover Dam.
- The area is the sum of whole HUC12 watersheds that hold a traced channel, so it is shown to three figures ("About
  68,500 sq mi"). It runs under the official drainage area where water is lost to sinks and diversions (the Lost
  Rivers and Raft River in the Snake basin, the Great Divide Basin in the Green) because those channels never reach
  the river on the map.
- `dams.json` maps a reservoir name to its dam. Natural lakes and any dam whose name could not be confirmed are left
  out, so they show as lakes without a dam marker. A `"<river id>/<name>"` key applies to one river only (two unrelated
  lakes are both called Emigrant Lake).

## Data notes

- Trips have a `river` field (river id); trips without one are Grand Canyon.
- The seed trip is written to localStorage once, guarded by the key
  `eddy.v1.seed2`. If you change the seed trip's shape, bump that key.
- Access points get ids `r0, r1, ...` by position in `access[]`; trips refer to
  launch/take-out by those ids, so append rather than reorder.

## Grand Canyon 2026 trip data

`data/trip.json` (crew, boats, cars, gear with per-person quantities, menu, payments, day notes) and
`data/trips/gc2026-ref.json` (read-only Info tab: constraints, camp jobs, Ceiba Q&A, shopping list,
Crew Council agendas and minutes, education plan, and the sunrise-to-sunrise sky log shown on each
Itinerary day) were generated from the planning spreadsheet. Course logins from the sheet are
deliberately not copied. Seed key `eddy.v1.seed5`: a never-edited seeded trip is replaced; an
edited one keeps its data and only gets the sheet's gear, menu, payments and day notes where empty.
Trip > Trip > "Reload planning-sheet data" replaces everything from the seed.

## Topo map and canyon sun

See `docs/TOPO_MAP_PLAN.md`. Every river has the Topo map and Sun & shade. Elevation comes from the open AWS Terrain
Tiles (USGS 3DEP/NED). Each rapid / camp / hike is placed on the river centerline by river mile (camps and hikes pushed
to their bank), and each camp gets a 360-degree terrain horizon at build time, which gives "direct sun in camp" times for
any date with no network.

Where the centerline comes from:

- **Grand Canyon**: traced from the terrain between surveyed anchors in `data/geo/anchors.json`.
- **The other 21 rivers**: the USGS National Hydrography Dataset main stem along the trip's run (the same network the
  Basin maps use), cut to the guide's put-in and take-out. The guide's river miles are pinned to it wherever a rapid,
  falls, bar, camp or creek in the guide shares its name with a USGS Geographic Names point on the line. The script
  keeps the longest chain of those points that runs downstream in mile order and checks the fit, so a namesake creek
  somewhere else is ignored. Where the names don't match (Rio Chama, Flaming Gorge, Westwater,
  Ruby-Horsethief) the line runs by the put-in, take-out and trip length. It prints each river's matches, scale and
  residual.

    python3 scripts/basin/centerline.py                   # all rivers without DEM anchors (needs the same Python setup as the Basin maps)
    python3 scripts/basin/centerline.py rogue --debug     # list every match and the chain kept
    npm run geo                 # every river (DEM tiles cache in .cache/dem)
    npm run geo -- rogue        # one river
    node scripts/geo/preview.mjs grand-canyon 130 140 out.png   # eyeball the line and pins on a hillshade

Surveyed GPS positions beat mile placement. To add them (from a guidebook GPX, a GIS export, or pins dropped
on a trip and exported from the app):

    node scripts/geo/import-coords.mjs grand-canyon camps.gpx           # dry run: shows each match
    node scripts/geo/import-coords.mjs grand-canyon camps.gpx --write   # saves data/geo/coords/grand-canyon.json
    npm run geo -- grand-canyon

Each matched camp then uses its GPS position for the map and its horizon, and also becomes a mile mark that
re-calibrates the river miles around it.

Offline: River > More (or Offline on the topo map) downloads a river's terrain, about 130 MB for the Grand
Canyon (10 km either side at full detail, wider at lower detail). On the iPhone it is saved as files in the
app's data folder (`src/geo/store.js`); on the web, in Cache Storage. The map, sun & shade and dropped pins
read only from there when there's no signal.

Rerun `npm run geo` after adding or renaming camps (horizons are keyed by `name@mile`). The trace report
prints traced vs official miles per segment; a `climb` warning means the path left the canyon floor, which
needs an extra anchor between those two.
